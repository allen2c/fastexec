# Implement FastExec and Pipeline core skeleton

## Description

Build the foundational `FastExec` and `Pipeline` classes with path-based registration and dispatch. This is the core skeleton upon which all other phases depend.

`FastExec` is the central app object (analogous to `FastAPI()`). `Pipeline` is analogous to `APIRouter` — it groups endpoints under a shared context. Endpoints are registered on a Pipeline with a path, and `app.exec("/path")` dispatches to the matching endpoint.

Key API surface:
```python
from fastexec import FastExec, Pipeline

app = FastExec(state={...})
pipeline = Pipeline()
pipeline.register("/users", get_users)        # explicit
@pipeline.register("/orders")                  # decorator
async def get_orders(): ...
app.include_pipeline(pipeline, prefix="/api")
result = await app.exec("/api/users")
```

## Acceptance Criteria

- [ ] `FastExec()` can be instantiated with no arguments
- [ ] `FastExec(state={...})` accepts initial app-level state accessible as `app.state.key`
- [ ] `Pipeline()` can be instantiated independently
- [ ] `pipeline.register("/path", fn)` registers a callable with a path
- [ ] `@pipeline.register("/path")` decorator syntax registers a callable
- [ ] `app.include_pipeline(pipeline)` includes a pipeline in the app
- [ ] `app.include_pipeline(pipeline, prefix="/api")` includes with a path prefix
- [ ] `await app.exec("/path")` dispatches to the correct endpoint and returns its result
- [ ] Prefix + path combines correctly for dispatch (e.g. `/api/v1` + `/users` → `/api/v1/users`)
- [ ] Both sync and async endpoint functions are supported transparently
- [ ] `app.exec("/nonexistent")` raises `LookupError` for unregistered paths
