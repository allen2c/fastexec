# Implement FastAPI response and exception compatibility

## Description

Ensure fastexec produces responses and exceptions consistent with FastAPI behavior:

- **response_model**: `pipeline.register("/path", fn, response_model=Model)` filters output through the model
- **status_code**: `pipeline.register("/path", fn, status_code=201)` sets response status
- **HTTPException**: `fastapi.HTTPException` raised in endpoints or dependencies propagates with correct status code and detail
- **RequestValidationError**: missing/invalid params raise `fastapi.exceptions.RequestValidationError`
- **Response objects**: endpoints can return `JSONResponse`, `Response` directly

All exceptions use FastAPI's exception classes — no custom exception types.

## Acceptance Criteria

- [ ] `response_model=` on `register()` filters output, stripping extra fields
- [ ] `status_code=` on `register()` sets the response status code
- [ ] `fastapi.HTTPException` raised in endpoint propagates with correct status_code and detail
- [ ] `fastapi.HTTPException` raised in a dependency propagates correctly
- [ ] Missing required query param raises `fastapi.exceptions.RequestValidationError`
- [ ] Wrong type for query param raises `fastapi.exceptions.RequestValidationError`
- [ ] Invalid body against Pydantic model raises `fastapi.exceptions.RequestValidationError`
- [ ] Endpoint returning `fastapi.responses.JSONResponse` passes through as-is
- [ ] Endpoint returning `fastapi.Response` passes through as-is
- [ ] `response_model` and `status_code` work together
- [ ] All 13 tests in `tests/v060/test_phase7_response_compat.py` pass
